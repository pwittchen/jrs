Benchmarks

The build is done before the daemon answers.

jrs is one native binary that starts in milliseconds and keeps nothing running between builds. On the same projects, built the same way, it finishes a no-op build in about 60 ms, five times faster than a warm Gradle daemon and more than ten times faster than Maven. It is slower where a warm compiler pays off: an API change, and a clean build of a large project or a workspace, where a warm Gradle daemon finishes up to one and a half times sooner. Five ways to build the same project

Gradle is measured three ways: with a daemon kept warm from the warm-up runs, the same with the configuration cache, and with --no-daemon, which is what a CI job or the first command of the day sees. On the workspace a fourth, --parallel, builds its modules at once, as jrs does.

Where jrs wins, and where it does not yet

Faster

  • Anything start-up bound. No-op builds in 64–84 ms on every project: 4–7× a warm Gradle daemon, 14–17× Maven, 26–35× Gradle without a daemon.
  • One-file edits. 210–380 ms on every project, 1.5–1.8× ahead of a warm daemon and 5–7× ahead of Maven.
  • Tests and test selection. Faster than a warm daemon on every project, now that the test JVM maps the JDK's and JUnit's classes: 763 ms against 0.80–0.88 s on 2000 classes, 419 ms against 0.67–1.79 s in a workspace. jrs test runs only the tests a change reaches: 424 ms against 2.8 s for Maven in the workspace.
  • Clean builds of small projects. 340–588 ms, ahead of the daemon again now that javac's cache is made where no build waits on it: 346 ms against 0.66–0.68 s on Spring Boot.
  • Fat jars, Spring Boot's included. 5.7–7.5× faster than shadowJar on a warm daemon, and 211 ms against bootJar's 514 ms.
  • Cold builds. 0.98–1.8 s with empty caches, against 1.6–3.3 s for Maven and 11.5–15 s for Gradle, which sets up its whole home first.
  • On CI. Against Gradle without a daemon and against Maven, jrs is faster in every cell.

Gradle's daemon still wins

  • An API change. jrs follows an API change in rounds and stops when a round changes no API, but Gradle still compiles in a warm compiler: 895 ms against 0.60–0.64 s on 2000 classes, 512 ms against 0.42–0.50 s in a workspace, and by 2–7% on the small projects too.
  • Clean builds of a big project or a workspace. 1.54 s against the daemon's 1.21–1.27 s on 2000 classes, nearly all of it javac. Six members build at once in 817 ms, 77 ms above their critical path, against the daemon's 0.66–0.75 s (GRADLE_GAPS).

How it was measured

  1. The same build, three times. Each project has a jrs.toml, a pom.xml and a build.gradle.kts for the same sources, dependencies, --release, JUnit 5 tests and fat jar. The generated projects get all three from one description.
  2. Checked before timed. No project is timed until every tool resolves the same runtime classpath, runs the same tests with no failures, prints the same output and builds a jar that starts.
  3. No network, no build cache. Every tool reads one local mirror of Maven Central and the Gradle Plugin Portal; jrs, Maven and Gradle all run with their build caches off.
  4. Default configuration. No tuning flag jrs has no counterpart for. Output goes to a file, never a terminal. Runs go round-robin over the tools.
  5. The setup. jrs 0.14.1, Maven 3.9.16 and Gradle 9.1.0 on Corretto 25.0.2, the machine below, on 2026-10-17. The four earlier passes, jrs 0.11.0 on 2026-10-14, jrs 0.12.0 on 2026-10-15, jrs 0.13.0 on 2026-10-16 and jrs 0.14.0 earlier on 2026-10-17, used the same machine and tool versions.

The rules, the scenarios and the harness are in specs/BENCHMARKS.md; the numbers and their reading in specs/BENCHMARKS_SUMMARY.md. Run it on your own machine: 

git clone https://github.com/pwittchen/jrs && cd jrs
JRS_BENCH_RECORD=1 cargo bench --bench compare   # fill the local mirror, once
cargo bench --bench compare                      # writes benchmarks/REPORT.md

Time it on your own project

jrs migrate writes a jrs.toml beside your pom.xml or Gradle build and leaves them in place, so the comparison costs one command. 

cd my-project
jrs migrate
time jrs build     # then once more, with nothing changed
