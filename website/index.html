A JVM build system, written in Rust.

jrs builds, tests, runs and packages a Java project from one jrs.toml. Kotlin, Scala and Groovy compile alongside. A small manifest, a committed lockfile, one binary, and no build script to write.

One manifest, no build script

        

          A project is a jrs.toml and a source tree. Resolution writes
          jrs.lock, which you commit. Everything under target/ can be
          thrown away and rebuilt.
        

        

          
          
        

      


      

        
What it does

        

          

            
Resolving

            

              Dependencies from Maven Central and your own repositories: transitive graphs,
              nearest-wins mediation, exclusions, classifiers, compile-only deps and SNAPSHOTs.
            

          

          

            
Pinning

            

              Every version and checksum in a committed jrs.lock. Downloads are
              verified into a shared cache, and --offline builds use only that cache.
            

          

          

            
Compiling

            

              Java, with Kotlin, Scala or Groovy beside it, calling each other both ways. Each
              compiler is fetched from Maven Central, pinned, and run on your JDK.
            

          

          

            
Testing

            

              JUnit 5 and 6, JUnit 4, Spock, Kotest, ScalaTest and MUnit. Filter by class, tag or
              method; get JUnit XML reports and JaCoCo coverage.
            

          

          

            
Packaging

            

              A plain, portable or fat jar with byte-identical output on every build, a trimmed
              jlink runtime, or a native installer via jpackage.
            

          

          

            
Running

            
Your main class, directly. Add --watch to rebuild on every change.

          

          

            
Tasks

            

              Code generators, checksums and chores declared in jrs.toml, run as
              subprocesses at fixed hooks, Java tools from Maven Central included. They can extend the build but never reorder it.
            

          

          

            
Migrating

            

              A one-shot jrs.toml from pom.xml, build.gradle
              or build.gradle.kts, Spring Boot builds included, with a report of what needs review.
            

          

          

            
Inspecting

            

              jrs tree --why, jrs outdated, jrs classpath,
              and jrs add / remove that keep your comments intact.
            

          

        

      


      

        
Install

        

          jrs is one binary. It needs a JDK 17 or newer on PATH or at
          JAVA_HOME, and fetches the Kotlin, Scala and Groovy compilers itself.
        


        

          
          
          
        


        

          
          

            

            
          

          
Installs into ~/.local/bin, which must be on your PATH. The Linux binaries are static and run on any distribution.

        


        

          

            
curl.exe -fsSLO https://github.com/pwittchen/jrs/releases/latest/download/jrs-x86_64-pc-windows-msvc.zip
tar -xf jrs-x86_64-pc-windows-msvc.zip jrs.exe

            
          

          
Run in PowerShell, then move jrs.exe to a directory on your PATH.

        


        

          

            
git clone https://github.com/pwittchen/jrs.git
cd jrs
cargo install --path .

            
          

          
Needs a Rust toolchain with edition 2024 support. The binary lands in ~/.cargo/bin.

        


        
Each release also ships a SHA256SUMS file for verifying the downloads.


        
Then

        


jrs init            # scaffold jrs.toml, a main class and its test
jrs run
jrs test
jrs migrate         # or start from an existing pom.xml / build.gradle

          
        

      


      

        
Status

        

          jrs is experimental, and it is not a replacement for Maven or Gradle. It builds
          single-module projects and implements a deliberately narrow subset of what those tools
          do: no plugin system, no build DSL, no multi-module reactor. Evaluate it against your
          own requirements before adopting it for production builds.
        

        

          The roadmap lists
          the known gaps, and the spec
          explains the design behind them.
