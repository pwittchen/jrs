A JVM build system, written in Rust.

jrs builds, tests, runs and packages a Java project from one jrs.toml. Kotlin, Scala and Groovy compile alongside. A small manifest, a committed lockfile, one binary, and no build script to write.

Status experimental

        

          jrs is experimental, and it is not a replacement for Maven or Gradle. It builds
          single projects and multi-module workspaces, and implements a deliberately narrow subset
          of what those tools do: no plugin system, no build DSL, no reactor — modules are declared,
          not configured. Evaluate it against your own requirements before adopting it for
          production builds.
        

        

          The roadmap lists
          the known gaps, and the spec
          explains the design behind them.
        

      


      

        
One manifest, no build script

        

          A project is a jrs.toml and a source tree. Resolution writes
          jrs.lock, which you commit. Everything under target/ can be
          thrown away and rebuilt.
        

        

          
          
        

      


      

        
What it does

        

          

            
Resolving

            

              Dependencies from Maven Central and your own repositories: transitive graphs,
              nearest-wins mediation, exclusions, classifiers, compile-only deps and SNAPSHOTs.
            

          

          

            
Pinning

            

              Every version and checksum in a committed jrs.lock. Downloads are
              verified into a shared cache, and --offline builds use only that cache.
            

          

          

            
Compiling

            

              Java, with Kotlin, Scala or Groovy beside it, calling each other both ways. Each
              compiler is fetched from Maven Central, pinned, and run on your JDK.
            

          

          

            
Testing

            

              JUnit 5 and 6, JUnit 4, Spock, Kotest, ScalaTest and MUnit. Only the test classes a
              change reaches run, split across JVMs; filter by class, tag or method, shard a suite
              across CI machines, get JUnit XML reports and JaCoCo coverage.
            

          

          

            
Packaging

            

              A plain, portable or fat jar with byte-identical output on every build, a trimmed
              jlink runtime, a native installer via jpackage, a GraalVM
              native executable, and a CycloneDX SBOM.
            

          

          

            
Running

            
Your main class, directly. Add --watch to rebuild and restart it on every change.

          

          

            
Caching

            

              Compiled classes and passing test runs restored from a build cache across branches,
              checkouts and jrs clean, locally or from a remote shared with CI.
            

          

          

            
Workspaces

            

              Several modules from one root: members that depend on each other by path, shared
              settings, one lockfile for all of them, and every command over the whole workspace
              or, with -p, one member and what it needs.
            

          

          

            
Tasks

            

              Code generators, checksums and chores declared in jrs.toml, run as
              subprocesses at fixed hooks, Java tools from Maven Central included. They can extend the build but never reorder it.
            

          

          

            
Migrating

            

              A one-shot jrs.toml from pom.xml, build.gradle
              or build.gradle.kts, Spring Boot and multi-module builds included, with a
              report of what needs review.
            

          

          

            
Inspecting

            

              jrs tree --why, jrs outdated, jrs audit for known
              vulnerabilities, jrs licenses, jrs classpath, and
              jrs add / remove that keep your comments intact.
            

          

        

      


      

        
Install

        

          jrs is one binary. It needs a JDK 17 or newer on PATH or at
          JAVA_HOME, and fetches the Kotlin, Scala and Groovy compilers itself.
        


        

          
          
          
          
          
        


        

          

            
curl -fsSL https://getjrs.dev/install.sh | sh

            
          

          
Picks the Apple Silicon or Intel build and installs it into ~/.local/bin. Add -s -- --to <dir> after sh to install elsewhere.

        


        

          

            
curl -fsSL https://getjrs.dev/install.sh | sh

            
          

          
Picks the x86_64 or ARM64 build and installs it into ~/.local/bin. The binaries are static and run on any distribution.

        


        

          

            
curl.exe -fsSLO https://github.com/pwittchen/jrs/releases/latest/download/jrs-x86_64-pc-windows-msvc.zip
tar -xf jrs-x86_64-pc-windows-msvc.zip jrs.exe

            
          

          
Run in PowerShell, then move jrs.exe to a directory on your PATH. On ARM64, download jrs-aarch64-pc-windows-msvc.zip instead.

        


        

          

            
cargo install --git https://github.com/pwittchen/jrs.git

            
          

          
On any platform with a Rust toolchain that supports edition 2024: builds the latest master and puts the binary in ~/.cargo/bin. To build a release instead, add --tag v<version>.

        


        

          

            
git clone https://github.com/pwittchen/jrs.git
cd jrs
cargo install --path .

            
          

          
Needs a Rust toolchain with edition 2024 support. The binary lands in ~/.cargo/bin.

        


        
Each release also ships a SHA256SUMS file for verifying the downloads, which the install script checks for you. From then on, jrs self check tells you whether a newer release is out and jrs self update installs it in place, checksum verified.


        
Then

        


jrs init            # scaffold jrs.toml, a main class and its test
jrs run
jrs test
jrs migrate         # or start from an existing pom.xml / build.gradle

          
        


        
Shell completions

        


source <(jrs completions bash)   # bash: in ~/.bashrc
source <(jrs completions zsh)    # zsh: in ~/.zshrc, after compinit

          
        

        
Tab completion for every command and flag. In zsh you can instead save the script as _jrs on your $fpath; that and fish are in the docs.

      


      

        

          

            
IntelliJ IDEA

            

              The jrs plugin imports a jrs.toml project the way the IDE imports a Maven or
              Gradle one, from jrs metadata: source roots, the JDK and every library.
              Build Project runs jrs build, so the IDE and the terminal share one
              target/.
            

          

          
        

        
    
          
  • A workspace imported as one module per member, depending on each other
    • 
          
  • Run configurations for jrs run, jrs test and jrs task, with the debugger and the test runner tree
    • 
          
  • jrs test on any test class or method, from the gutter
    • 
          
  • A jrs tool window with the project's tasks and dependencies
    • 
          
  • Completion and unknown-key warnings in jrs.toml; jrs add / remove from the menu
    • 
          
  • A reload banner when jrs.toml or jrs.lock changes
    • 
        

        

        
        
        

          The plugin is on the
          JetBrains Marketplace: install it
          with the button above, or from Settings | Plugins | Marketplace in the
          IDE. Each release also
          ships it as jrs-intellij.zip, for Install Plugin from Disk…
          in the same dialog's gear menu. Needs IntelliJ IDEA 2026.2 or newer. More in
          the docs.
        

      


      

        

          

            
GitHub Actions

            

              The setup-jrs action installs jrs on Linux, macOS and Windows runners,
              checksum verified, and can cache its dependencies and compiled classes between runs.
            

          

          
        

        


- uses: actions/setup-java@v6
  with: { distribution: temurin, java-version: '21' }
- uses: pwittchen/setup-jrs@v1
  with: { cache: true }
- run: jrs test

          
        

        

          It is on the
          GitHub Marketplace, with
          its source in pwittchen/setup-jrs.
          version: manifest installs the release your jrs.toml asks for.
          More in the docs.
